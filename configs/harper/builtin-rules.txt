# Harper built-in rules prose-lint enables next to the Prose* Weir
# rules. One name per line; lines starting with # are comments. Each
# rule needs a fixtures/<Rule>.bad.md and fixtures/<Rule>.good.md pair,
# so a Harper upgrade that changes a rule fails the build the same way
# a Weir edit does. Rules that misread identifiers, table cells, or
# technical abbreviations (SpellCheck, SentenceCapitalization,
# OxfordComma, the Expand* family) stay off on purpose. So do three
# rules whose only hits in technical prose were false: RedundantThat
# fires on every grammatical `that that` (`the rule that that file
# defines`), MultipleFrequencyAdverbs on a schedule with its exception
# (`runs daily, never on weekends`), and Oxymorons on `found missing`.
